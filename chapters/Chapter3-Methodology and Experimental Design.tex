\section{Methodological Overview}
The experimental framework contains four principal routes: \ac{AWQ} as
a weight-only reference, SmoothQuant as a joint weight--activation
reference, a project-specific \ac{W4A8} pipeline, and NestQuant as a
structured low-bit method that extends the quantization scope to model
weights, runtime activations and the key--value cache.

\section{Model and Experimental Context}
\subsection{Base Model and Quantization Scope}
All experiments use Llama-3.2-3B-Instruct as the common source model. The architecture contains 28 Transformer decoder layers and 3072 hiddendimensions , an intermediate feed-forward dimension of 8,192,24 attention heads and eight key--value heads, with a head dimension of 128~\cite{meta2024llama32}. The source model is represented using BF16 parameters and provides the full-precision reference for the principal cross-method quality and memory comparisons.

The common weight-quantization scope is defined at the Linear-projection level. Each decoder layer contains 7 target Linear modules: the query, key, value and output projections in the self-attention block, together with the gate, up and down projections in the feed-forward network. So the total number of target modules is 
\begin{equation}
N_{\mathrm{Linear}}
=
28 \times 7
=
196 .
\label{eq:number-linear-modules}
\end{equation}

These modules contain 2,818,572,288 target weight elements. And normalization parameters, language-model heads and other non-target tensors remain outside the common Linear-layer quantization scope unless explicitly stated. The detailed information of the model will be shown in table \ref{tab:model-architecture-scope}.

\subsection{Calibration Data}

UltraChat-200k was used as the data source for the calibration and
evaluation procedures in this project. The dataset contains
instruction-following conversations consisting of user and assistant
turns. Calibration samples were drawn from the \texttt{train\_sft}
split, while the \texttt{test\_sft} split was reserved for the common
model-quality evaluation.

The calibration procedure is different from the quantization pipelines. The retained AWQ, smooth quant and project-specific W4A8 configurations used 64 representative calibration conversations. NestQuant used the same UltraChat-based experimental framework with a 2,048-token context for its calibration procedure. For all pipelines, calibration data were kept separate from the \texttt{test\_sft} examples used for the final cross-method comparison. This separation prevents the evaluation data from contributing to the selection of quantization parameters and provides a consistent basis for comparing the low-precision configurations.

\subsection{Common Running Protocol}
To provide a consistent basis for cross-method comparison, all principal
model configurations were evaluated using the same held-out
UltraChat-200k \texttt{test\_sft} split. The evaluation included the
BF16 baseline together with AWQ, SmoothQuant, specific W4A8
pipeline and the retained NestQuant configurations. Using a common test
set ensures that differences in model quality are associated with the
quantization configuration rather than with differences in evaluation
data.

The evaluation followed an assistant-response-only scoring protocol.
User messages and preceding conversational turns were retained as model
context, but only assistant-response tokens contributed to the reported
negative log-likelihood and perplexity. The final prepared evaluation
set contained 73,150 assistant responses and 4,500,809 scored assistant
tokens. A maximum sequence length of 256 tokens and a maximum scored
assistant-response length of 64 tokens were used, with a batch size of
one. Three examples were processed as warm-up before measurement and
were excluded from the timed evaluation. Dataset loading and
tokenization were also excluded from the measured execution region. Table \ref{tab:common-evaluation-protocol} shows the database in detail.

\section{Quantization Pipelines}


\subsection{AWQ Pipeline}
In AWQ retained configuration, the eligible Linear-layer weights are
quantized using symmetric grouped INT4 with a group size of 128. For each weight group \(G_g\), symmetric INT4 quantization was applied
using a group-specific scale: \begin{equation}
s_g
=
\frac{\max_{w_i \in G_g}|w_i|}
     {2^{b-1}-1},
\qquad b=4,
\label{eq:awq-group-scale}
\end{equation}

and with the integer representation:

\begin{equation}
q_i
=
\operatorname{clip}
\left(
\operatorname{round}
\left(
\frac{w_i}{s_g}
\right),
-8,7
\right),
\label{eq:awq-int4}
\end{equation}

so the reconstructed weight is

\begin{equation}
\hat{w}_i=s_g q_i.
\label{eq:awq-dequant}
\end{equation}
Quantization is applied to the query, key, value and output projections
of the attention block and the gate, up and down projections of the
feed-forward block. Across the 28 decoder layers, this gives 196 target
Linear modules. The \texttt{lm\_head} and other non-target tensors
remain outside this quantization scope. Runtime activations and the key--value cache remain at higher
precision, producing the W4A16KV16 operating point. This configuration
therefore isolates the effect of low-bit weight representation without
introducing activation or cache quantization. The whole process is shown in Figure \ref{fig:awq-process}
\begin{figure}[htbp]
    \centering
    \includegraphics[width=\textwidth]
    {imgs/awq-pipeline-visual.png}
    \caption{AWQ implementation.}
    \label{fig:awq-process}
\end{figure}

For the formal runtime path, the compressed weights are converted to
the ATen packed INT4 representation before measured inference. All 196
target Linear modules are replaced by the packed implementation and
the decompression path associated with the source compressed
checkpoint is removed. The packed representation is verified after
model setup and inference so that checkpoint compression is not
mistaken for a genuinely compressed runtime representation.


\subsection{SmoothQuant Pipeline}
Unlike weight-only quantization,
SmoothQuant explicitly addresses activation outliers before integer
quantization by redistributing part of the quantization difficulty from
activations to the corresponding weight channels.

For a Linear layer

\begin{equation}
\mathbf{Y}
=
\mathbf{W}\mathbf{X},
\label{eq:sq-linear}
\end{equation}

a positive diagonal scaling matrix
\(\mathbf{S}=\operatorname{diag}(s_1,\ldots,s_d)\) can be introduced
without changing the original floating-point operation:

\begin{equation}
\mathbf{Y}
=
\mathbf{W}\mathbf{X}
=
\left(\mathbf{W}\mathbf{S}\right)
\left(\mathbf{S}^{-1}\mathbf{X}\right).
\label{eq:sq-equivalent-transform}
\end{equation}

The channel-wise smoothing coefficient is determined from the observed
activation and weight ranges as

\begin{equation}
s_j
=
\frac{
\left(\max |X_j|\right)^{\alpha}
}{
\left(\max |W_j|\right)^{1-\alpha}
},
\label{eq:sq-smoothing-factor}
\end{equation}

where \(j\) denotes an input channel and \(\alpha\) controls how much
quantization difficulty is migrated from activations to weights. The
retained implementation used

\begin{equation}
\alpha = 0.8.
\end{equation}

Representative UltraChat \texttt{train\_sft} inputs were used to
collect the activation statistics required to determine the smoothing
transformation. The transformation itself was applied before runtime
inference, allowing the resulting activation distribution to be more
suitable for low-precision representation.

After smoothing, the target Linear-layer weights were represented using
INT8, while their input activations were quantized dynamically to INT8
on a per-token basis. For an activation vector \(\mathbf{x}\), the
symmetric dynamic activation scale was calculated as

\begin{equation}
s_x
=
\frac{\max_i |x_i|}{127},
\label{eq:sq-a8-scale}
\end{equation}

with the corresponding INT8 representation

\begin{equation}
q_i^{(x)}
=
\operatorname{clip}
\left(
\operatorname{round}
\left(
\frac{x_i}{s_x}
\right),
-127,127
\right).
\label{eq:sq-a8-quant}
\end{equation}

So the resulting operating point is denoted W8A8KV16: both the target
weights and runtime activations use 8-bit representations, while the
key--value cache remains at 16-bit precision. Here is the entire process of smooth quant in Figure \ref{fig:smoothquant-pipeline-visual}

\end{figure}

\subsection{Project-Specific W4A8 Pipeline}


The implementation of specific W4A8 starts from the same BF16
Llama-3.2-3B-Instruct checkpoint used by the other quantization
pipelines. The target scope consists of the query, key, value and output
projections in the attention block together with the gate, up and down
projections in the feed-forward block. Across the 28 decoder layers,
this corresponds to 196 target Linear modules, with
\texttt{lm\_head} excluded from quantization.

Representative UltraChat \texttt{train\_sft} inputs were first passed
through the BF16 model to collect activation statistics for the target
Linear modules. Candidate channel-wise transformations were then
constructed from two scale families: a SmoothQuant-style
activation--weight formulation and an activation-driven formulation
inspired by AWQ.

A total of 20 candidate scaling configurations were evaluated under the
intended W4A8 numerical path. Let

\begin{equation}
\mathcal{S}
=
\left\{
s^{(1)},s^{(2)},\ldots,s^{(20)}
\right\}
\label{eq:w4a8-candidate-scales}
\end{equation}
denote the candidate scale set. For a candidate
\(s\in\mathcal{S}\), the corresponding block output after the simulated
W4A8 transformation is denoted
\(\mathbf{Y}_{\mathrm{W4A8}}(s)\). The retained scale is selected by
minimising the reconstruction error relative to the BF16 block output:

\begin{equation}
s^{*}
=
\arg\min_{s\in\mathcal{S}}
\frac{1}{N}
\sum_{n=1}^{N}
\left\|
\mathbf{Y}^{(n)}_{\mathrm{BF16}}
-
\mathbf{Y}^{(n)}_{\mathrm{W4A8}}(s)
\right\|_2^2 .
\label{eq:w4a8-scale-search}
\end{equation}

The final W4 checkpoint is executed using the ATen packed INT4
weight path, while the dynamic A8 stage is implemented using a custom
Triton kernel. The persistent weight representation therefore remains
compressed during runtime inference. The complete W4A8 workflow will be shown in figure \ref{fig:w4a8-pipeline-visual}

\subsection{NestQuant Pipeline}
NestQuant was implemented as the principal structured low-bit
quantization method in this study
\cite{savkin2025nestquantnestedlatticequantization}. In contrast to
AWQ, SmoothQuant and the project-specific W4A8 pipeline, which use
scalar or grouped quantization, NestQuant represents groups of values
using structured vector quantization. The method further allows the
quantization scope to be extended from model weights to runtime
activations and the key--value cache.

The retained implementation uses an 8-dimensional \(E_8\) lattice,
Hadamard rotation and quantization-aware LDLQ (QA-LDLQ). The project
configuration uses

\begin{equation}
q = 14,
\qquad
k = 4,
\label{eq:nestquant-qk}
\end{equation}

where \(q\) controls the discrete lattice-code representation and
\(k\) denotes the number of candidate scaling coefficients available
during vector quantization.

Before lattice quantization, the relevant tensors are transformed using
an orthogonal Hadamard rotation. The purpose of this transformation is
to redistribute large-magnitude coordinates across dimensions and
therefore reduce the effect of isolated outliers on low-bit
quantization.

Let \(\mathbf{R}\) denote an orthogonal rotation matrix satisfying

\begin{equation}
\mathbf{R}^{\mathrm{T}}\mathbf{R}
=
\mathbf{I}.
\label{eq:nestquant-orthogonal}
\end{equation}

For a vector \(\mathbf{x}\), the rotated representation is

\begin{equation}
\widetilde{\mathbf{x}}
=
\mathbf{R}\mathbf{x}.
\label{eq:nestquant-rotation}
\end{equation}

Because the transformation is orthogonal, Euclidean geometry is
preserved while the coordinate distribution presented to the
quantizer is changed. The transformed tensors are divided into 8-dimensional vectors

\begin{equation}
\mathbf{v}_j \in \mathbb{R}^{8},
\label{eq:nestquant-vector-block}
\end{equation}

which are subsequently represented using the structured \(E_8\)
lattice quantizer.
For each 8-dimensional vector \(\mathbf{v}\), NestQuant evaluates the
available scaling coefficients
\(\{\beta_1,\ldots,\beta_k\}\). For scale \(\beta_p\), the candidate
reconstruction is

\begin{equation}
\widehat{\mathbf{v}}_{p}
=
\beta_p
\operatorname{Decode}
\left[
\operatorname{Encode}
\left(
\frac{\mathbf{v}}{\beta_p}
\right)
\right].
\label{eq:nestquant-vector-reconstruction}
\end{equation}

The scaling coefficient is selected by minimising the vector
reconstruction error,

\begin{equation}
p^{*}
=
\arg\min_{p\in\{1,\ldots,k\}}
\left\|
\mathbf{v}
-
\widehat{\mathbf{v}}_{p}
\right\|_2^2 ,
\label{eq:nestquant-beta-selection}
\end{equation}

giving the retained reconstruction

\begin{equation}
\widehat{\mathbf{v}}
=
\widehat{\mathbf{v}}_{p^{*}} .
\label{eq:nestquant-vector-output}
\end{equation}

This differs from element-wise INT4 quantization because a complete
8-dimensional vector is represented jointly using a structured lattice
code and a selected scaling coefficient.

NestQuant combines lattice quantization with second-order error
feedback. For a weight matrix \(\mathbf{W}\) and original layer input
\(\mathbf{X}\), conventional second-order weight quantization considers
the effect of replacing \(\mathbf{W}\) by a quantized matrix
\(\mathbf{U}\).

When activations are also quantized, however, the layer receives
\(\mathbf{X}+\mathbf{Z}\), where \(\mathbf{Z}\) denotes activation
quantization error. The resulting output error is therefore

\begin{equation}
\boldsymbol{\delta}(\mathbf{U})
=
\mathbf{W}\mathbf{X}
-
\mathbf{U}
\left(
\mathbf{X}+\mathbf{Z}
\right).
\label{eq:nestquant-output-error}
\end{equation}

QA-LDLQ seeks the quantized weight matrix

\begin{equation}
\mathbf{U}^{*}
=
\arg\min_{\mathbf{U}\in\mathcal{C}_{Q}}
\mathbb{E}
\left[
\left\|
\boldsymbol{\delta}(\mathbf{U})
\right\|_2^2
\right],
\label{eq:qa-ldlq-objective}
\end{equation}

where \(\mathcal{C}_{Q}\) denotes the set of permitted quantized
representations.

The second-order activation matrix is defined as

\begin{equation}
\mathbf{H}
=
\mathbb{E}
\left[
\mathbf{X}\mathbf{X}^{\mathrm{T}}
\right],
\label{eq:nestquant-hessian}
\end{equation}

while activation-quantization noise contributes

\begin{equation}
\mathbf{J}
=
\mathbb{E}
\left[
\mathbf{Z}\mathbf{Z}^{\mathrm{T}}
\right].
\label{eq:nestquant-noise}
\end{equation}

The QA-LDLQ transformation produces the modified weight target

\begin{equation}
\widetilde{\mathbf{W}}
=
\mathbf{W}\mathbf{H}
\left(
\mathbf{H}+\mathbf{J}
\right)^{-1}.
\label{eq:qa-ldlq-target}
\end{equation}

Standard LDLQ-style sequential error feedback is then applied to
\(\widetilde{\mathbf{W}}\) using
\(\mathbf{H}+\mathbf{J}\). This allows the weight-construction process
to account explicitly for the additional numerical error introduced by
low-bit activations.

Four principal NestQuant configurations are evaluated, as summarized configurations form a controlled expansion of quantization scope.
W4.25A16KV16 represents the weight-quantized NestQuant configuration.
W4.25A16KV4 additionally reduces the precision of the key--value cache,
whereas W4.25A4KV16 introduces low-bit activations while retaining the
higher-precision cache. Finally, W4.25A4KV4 applies low precision across
weights, activations and the key--value cache.

The experimental structure can therefore be represented as

\begin{equation}
\mathrm{W4.25A16KV16}
\begin{cases}
\longrightarrow \mathrm{W4.25A16KV4}, & \text{KV ablation},\\[2mm]
\longrightarrow \mathrm{W4.25A4KV16}, & \text{activation ablation},\\[2mm]
\longrightarrow \mathrm{W4.25A4KV4},  & \text{combined scope}.
\end{cases}
\label{eq:nestquant-scope-tree}
\end{equation}

This design separates the effect of activation precision from that of
the key--value cache instead of changing both simultaneously. The entire process is shown in Figure \ref{fig:nestquant-pipeline}

\section{Evaluation Protocol and Metrics}
The evaluation framework separates model quality from deployment
efficiency. Model quality is assessed using negative log-likelihood and
perplexity under the common UltraChat evaluation protocol described
previously. Deployment efficiency is evaluated separately using model
storage, peak GPU memory and runtime performance. This distinction is
important because a lower numerical bit width does not necessarily
produce a proportional improvement in memory usage or execution speed.


\paragraph{Negative log-likelihood and perplexity.}

Model quality is primarily evaluated using assistant-response
perplexity. For \(N\) scored assistant tokens, the mean negative
log-likelihood is

\begin{equation}
\mathrm{NLL}
=
-\frac{1}{N}
\sum_{t=1}^{N}
\log
p
\left(
x_t \mid x_{<t}
\right),
\label{eq:evaluation-nll}
\end{equation}

where only assistant-response positions contribute to the summation.
User messages and previous conversation turns are retained as context
but are masked from the loss calculation.

Perplexity is then obtained from

\begin{equation}
\mathrm{PPL}
=
\exp
\left(
\mathrm{NLL}
\right).
\label{eq:evaluation-ppl}
\end{equation}

A lower perplexity indicates better preservation of the predictive
behaviour of the reference model under the same evaluation stream.


\paragraph{Relative quality degradation.}

To compare quantized configurations with their corresponding reference,
the relative increase in perplexity is calculated as

\begin{equation}
\Delta_{\mathrm{PPL}}(\%)
=
100
\left(
\frac{\mathrm{PPL}_{q}}
     {\mathrm{PPL}_{r}}
-1
\right),
\label{eq:relative-ppl-increase}
\end{equation}

where \(\mathrm{PPL}_{q}\) denotes the perplexity of the quantized model
and \(\mathrm{PPL}_{r}\) denotes the selected reference.

The BF16 model is used as the reference for the principal cross-method
comparison. For the NestQuant scope ablation,
W4.25A16KV16 is used as the internal reference so that the incremental
effects of activation and KV-cache quantization can be evaluated
independently.


\paragraph{Runtime model storage.}

Model-tensor storage is measured from the tensor representation retained
by the executable model. Shared or aliased storage is counted only once
to avoid double counting. The percentage reduction relative to a
reference configuration is

\begin{equation}
R_{\mathrm{storage}}(\%)
=
100
\left(
1-
\frac{S_q}{S_r}
\right),
\label{eq:storage-reduction}
\end{equation}

where \(S_q\) and \(S_r\) denote the runtime model-tensor storage of the
quantized and reference configurations, respectively.

Serialized checkpoint size is treated separately from runtime
model-tensor storage because the on-disk representation may contain
packing metadata, scales and other auxiliary information.


\paragraph{Effective physical bit rate.}

For a packed representation containing \(N_w\) target weights and
occupying \(S\) bytes, the effective physical bit rate is defined as

\begin{equation}
b_{\mathrm{eff}}
=
\frac{8S}{N_w}.
\label{eq:effective-bit-rate}
\end{equation}

This metric describes the actual physical storage requirement of the
selected packed representation and therefore includes the relevant
side information rather than only the nominal quantization code width.
This distinction is particularly important for the W4.25 NestQuant
representation.


\paragraph{GPU-memory measurement.}

GPU-memory behaviour is evaluated using CUDA allocated-memory
statistics. Memory counters are reset after model construction and
runtime setup so that one-off checkpoint loading and representation
conversion do not determine the reported inference peak.

Peak allocated GPU memory is recorded during the measured execution
region. The relative reduction is calculated as

\begin{equation}
R_{\mathrm{GPU}}(\%)
=
100
\left(
1-
\frac{M_q}{M_r}
\right),
\label{eq:gpu-memory-reduction}
\end{equation}

where \(M_q\) and \(M_r\) are the peak allocated GPU-memory values of
the quantized and reference implementations, respectively.

The reported memory therefore characterizes the executable runtime
representation rather than temporary memory required during model
loading or conversion.


\paragraph{Runtime performance.}

Runtime performance is evaluated independently from perplexity and
memory. Throughput is defined as

\begin{equation}
\mathrm{Throughput}
=
\frac{N_{\mathrm{processed}}}
     {T_{\mathrm{eval}}},
\label{eq:evaluation-throughput}
\end{equation}

where \(N_{\mathrm{processed}}\) is the number of processed tokens and
\(T_{\mathrm{eval}}\) is the corresponding measured execution time.

For paired runtime measurements, speedup relative to the matched
reference is calculated as

\begin{equation}
\mathrm{Speedup}
=
\frac{T_{\mathrm{reference}}}
     {T_{\mathrm{quantized}}}.
\label{eq:evaluation-speedup}
\end{equation}

If the value is greater than one indicates that the quantized implementation is
faster than its reference.

Eager execution and CUDA Graph execution are considered separately
because graph replay can reduce Python and kernel-launch overhead.
Consequently, runtime performance is interpreted as a property of the
combination of quantization representation and execution backend rather
than of nominal bit width alone.
