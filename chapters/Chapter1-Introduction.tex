\section{Background}

\ac{LLM}s have become a major component of modern natural-language processing systems, supporting applications including conversational interaction, text generation, summarisation, question answering and reasoning. However, their increasing capability has been accompanied by substantial growth in model size and inference cost. Although the computational expense of training large models is considerable, deployment introduces a separate set of engineering constraints: model parameters must remain accessible during inference, intermediate activations must be processed at every layer, and autoregressive generation requires previously computed attention states to be retained. Consequently, practical \ac{LLM} deployment is constrained not only by arithmetic throughput, but also by memory capacity, memory bandwidth and the efficiency with which model data can be moved through the hardware.

The most persistent component of this memory footprint is the model weight set. Transformer-based \ac{LLM}s contain large collections of linear-layer parameters in the attention and feed-forward sub-networks. When these parameters are stored using 16-bit floating-point formats such as FP16 or BF16, a model containing billions of parameters requires several gigabytes of memory before runtime activations or the key--value cache are considered. During inference, these weights must repeatedly be accessed by matrix operations throughout the network. Reducing the number of bits required to represent each weight can therefore provide a direct reduction in model storage and in the volume of data that must be transferred from memory during inference.

The performance implications of this memory traffic depend on the inference phase. During prompt processing, commonly referred to as the \emph{prefill} phase, multiple tokens are processed in parallel and matrix operations can exhibit comparatively high computational intensity. During autoregressive \emph{decode}, by contrast, one or a small number of new tokens are typically processed at each generation step. The arithmetic work performed per weight access is therefore reduced, making memory movement an increasingly important contributor to inference cost. This distinction motivates low-precision representations that reduce the amount of weight data transferred for each generated token, particularly when inference is limited by memory bandwidth rather than raw floating-point compute capability.

These constraints are particularly relevant to smaller LLMs intended for deployment on limited hardware. This dissertation uses Llama-3.2-3B-Instruct as its principal evaluation model. At approximately three billion parameters, it provides a useful intermediate scale: the model is sufficiently large for weight storage, activation precision and KV-cache behaviour to remain meaningful engineering concerns, while being sufficiently compact to permit repeated calibration, quantization and evaluation within the computational resources available to this project.

\subsection{\ac{LLM} deployment challenges}
A first-order indication of this deployment challenge can be obtained directly from the number of model parameters. If a model contains \(N\) parameters and each parameter is represented using \(b\) bits, the raw storage requirement of the weights can be approximated ~\ref{eq:weights},
\begin{equation}
S_{\mathrm{weights}}=N\frac{b}{8}\quad \text{bytes}.
\label{eq:weights}
\end{equation}For example, a three-billion-parameter model represented using 16-bit floating-point weights requires approximately\[3\times10^{9}\times\frac{16}{8}\approx 6~\mathrm{GB}\]for the parameter payload alone. At the same numerical precision, a model containing 7 billion parameters requires approximately \(14~\mathrm{GB}\), a 70-billion-parameter model requires approximately \(140~\mathrm{GB}\), and a model at the 405-billion-parameter scale approximately \(810~\mathrm{GB}\). These estimates do not include activations, the key--value cache, temporary computational buffers, framework overheads, memory fragmentation or other runtime allocations. The actual hardware requirement is therefore greater than that suggested by the stored parameters alone.

This scaling creates an immediate memory-capacity problem. A model can only be executed on a GPU if the tensors required for inference can be accommodated within the available device memory. Models that exceed the memory capacity of a single accelerator must therefore rely on techniques such as model sharding across multiple GPUs, CPU or storage offloading, or reductions in batch size and sequence length. Although these strategies enable larger models to run, they can increase system complexity and introduce additional communication or data-transfer overhead. Consequently, reducing the memory footprint of the model itself can directly broaden the range of hardware on which it can be deployed.

The inference-memory footprint also extends beyond model weights. Intermediate activations are produced as information propagates through the attention and feed-forward components of each Transformer block. Their size depends on factors including sequence length, batch size and hidden-state dimensionality. Unlike model weights, activations are generated dynamically from the current input and therefore cannot simply be quantized once and stored offline. Reducing their precision consequently requires a runtime quantization strategy and must account for the statistical characteristics of activation values.

\subsection{Motivation for low-bit quantization}
Quantization provides a direct approach to reducing the numerical representation cost of neural-network tensors. Rather than storing and processing every value using a high-precision floating-point representation, quantization maps values onto a smaller set of representable levels. In the context of LLM deployment, \ac{PTQ} is particularly attractive because it is applied to an already trained model and therefore does not require the original large-scale training process to be repeated. The theoretical storage benefit is straightforward. If a three-billion-parameter model requires approximately \(6~\mathrm{GB}\) for its weights at 16-bit precision, reducing the raw weight representation to 8 bits would ideally reduce this quantity to approximately \(3~\mathrm{GB}\), while a 4-bit representation would reduce it to approximately \[ 3\times10^{9}\times\frac{4}{8} \approx 1.5~\mathrm{GB}. \] Under this simplified calculation, moving from a 16-bit to a 4-bit weight representation corresponds to a fourfold reduction in the raw number of bits used to store the weights. Such reductions can be particularly valuable when deployment is constrained by GPU memory or by the amount of parameter data that must be moved during inference. 

The principal difficulty is that reducing numerical precision also reduces the number of values that can be represented. A quantizer must replace the original high-precision tensor values with nearby low-precision representations, introducing a quantization error. As bit width decreases, this approximation generally becomes more aggressive, and errors introduced into weights or intermediate tensors can propagate through subsequent Transformer layers. The practical objective is therefore not simply to minimise the nominal number of bits, but to achieve an appropriate balance between the reduction in representation cost and the resulting degradation in model quality. This motivates a central trade-off considered throughout this dissertation: \[ \boxed{ \mathrm{Model~Quality} \quad \longleftrightarrow \quad \mathrm{Compression} } \] However, bit width alone does not completely describe a quantized model. An equally important consideration is \emph{quantization scope}: which tensor classes within the inference process are actually represented at reduced precision. At the most conservative end of this design space, only the model weights are quantized. A configuration such as W4A16KV16 reduces weight precision to four bits while retaining the activations and KV cache at higher precision. Weight-only quantization can obtain substantial reductions in static parameter storage while limiting the number of locations at which quantization error enters the inference computation.
